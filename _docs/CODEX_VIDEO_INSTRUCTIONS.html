2. 作り方の方針（最優先・迷ったらここに戻る）

画面が動いているところを、できるだけ長く見せる。
見る人は「文字の説明」ではなく「画面が動いて仕事が終わる様子」で理解する。 1つの操作（クリック → 反応 → 結果が出る）は、目で追える速さで最後まで見せきる。
そのぶん、機能の説明は削ってよい。言葉で足りるものは字幕1行に畳むか、丸ごと落とす。 「全機能を見せる」より「主要な流れが目で分かる」を採る。

これが意味すること

  • 演出を速める（倍率で圧縮する）のは最後の手段。まず見せる対象を減らす。 1シーンに data-fx の寄りが5つあるなら、いちばん効く2つに絞って、そのぶん1つ1つを長く見せる
  • 1つの動きに最低 2.5〜3 秒。クリックの波紋 → 画面の反応 → トーストまでを、途中で切らない
  • 尺が足りなければ、足してよい。下の「尺を伸ばす手順」を使う。全体が 206.7 秒より長くなること自体は問題ない
  • ナレーションが無い区間を怖がらない。音が無くても画面が動いていれば伝わる。むしろ「見せ場」は黙って見せたほうが良い
  • 逆に、静止画のまま字幕だけ変わる時間は作らない。そこは削るか、画面を動かす

削ってよいもの / 残すもの

例
削ってよい補足の data-fx ラベル、細かい設定項目の紹介、同じことを言い換えた字幕、 一覧の行数（3行あるものは2行でよい）、脇のパネル
残すクリック → 反応 → 結果（トースト・行の追加・状態の変化）の一連。 タイプ演出やカウントアップなど時間で意味が出るもの。画面の遷移そのもの

尺を伸ばす手順（音声も一緒に伸ばす）

あるシーンをもっと長く見せたい場合、そのシーン以降の音声を後ろへずらして間を作る。音声の作り直しは要らない（無音を挟むだけ）。

# 1. どの行から何秒ずらすかを決める（例: No.15 以降を +4 秒）
python3 - <<'EOS'
import json, pathlib
p = pathlib.Path('_audio/timeline_v2.json'); tl = json.loads(p.read_text(encoding='utf-8'))
FROM_NO, SHIFT = 15, 4.0
for r in tl["rows"]:
    if r["no"] >= FROM_NO: r["start"] += SHIFT; r["end"] += SHIFT
tl["total"] = round(max(r["end"] for r in tl["rows"]) + 0.5, 1)
p.write_text(json.dumps(tl, ensure_ascii=False, indent=1), encoding='utf-8')
# cues_v2.json（合成用）も同じだけずらす
c = pathlib.Path('_audio/cues_v2.json'); cues = json.loads(c.read_text(encoding='utf-8'))
byno = {r["no"]: r for r in tl["rows"]}
for cue in cues:
    row = next((r for r in tl["rows"] if abs(r["start"] - cue["start"]) < 0.01 or r.get("read") == cue["text"]), None)
    if row: cue["start"], cue["end"] = row["start"], row["end"]
c.write_text(json.dumps(cues, ensure_ascii=False, indent=1), encoding='utf-8')
print("total", tl["total"])
EOS

# 2. 音声を合成し直す（無音が挟まるだけ。声は録り直さない）
cd _audio && CUES=cues_v2.json TOTAL=<新しい total> python3 assemble.py ../narration.mp3

4. 既存エンジンの仕様（<script> は原則さわらない）

1440×810 の設計フレームに .scene を並べ、時刻 t で表示を切り替える自作エンジン。再生中は映像の時刻を narration.mp3 の currentTime に従わせているので、音とズレない。

シーンの単位

<section class="scene" data-start="19.3" data-end="50.4" data-nav="/list-build" data-step="1"
         data-scroll="0:0,7.3:0,8.6:1020"> … </section>
  • data-start / data-end … 絶対秒（タイムライン上の位置）
  • data-nav … サイドバーで光らせるパス、data-step … 進行ボードの工程番号
  • data-scroll … 相対秒:スクロール量 の並び。ページを送る演出
  • class="scene full" data-cinema="1" … 全画面（サイドバー・ヘッダを出さない）。タイトルカードはこれ

シーン内部の演出（すべてそのシーンの開始からの相対秒）

属性 / クラス意味
data-in / data-out + class="cue"フェードで出す／消す。class="show" は瞬間表示
data-fx="開始:終了:ラベル"その要素に寄って枠とラベルを出す。data-fxz で倍率
data-click="秒"クリックの波紋
data-type="文字" data-in data-durタイプ演出
data-count="0,32780" data-in data-dur数字のカウントアップ
data-sel / data-on行の選択／ピルの点灯
.toast > .banner.ok画面上部のトースト
.fullcard > .fc画面全体を覆う白カード（書面・Excel の見せ場で使用中）

字幕とチャプター

const TOTAL = 213;                    // ← 206.7 に変える
const CH = [ [秒, '章ラベル', '章タイトル', ''] , … ];   // 章の頭でカードが出る
const CAPS = [ [開始, 終了, '字幕', '読み(任意)'] , … ]; // 画面下の字幕。読みは記録用

倍率のかけ方: そのシーンの data-in / data-out / data-click / data-sel / data-on / data-dur と data-fx の2つの秒、data-scroll の各キーの秒を、いずれも × 倍率 して丸める（小数第1位）。 掛けたあと どれも新しい尺を超えないことを必ず検算する。超えるものは手前に詰める。

7. タイトルカードの作り方

「左上に出ている機能名を、いったん画面センターに2秒出してから中身に入る」が要件。既存の .scene.full[data-cinema] と同じ作りにする。

<section class="scene full" data-cinema="1" data-start="66.2" data-end="68.2" data-step="4">
  <div class="tcard">
    <div class="tcard-eyebrow">工程4</div>
    <h2 class="tcard-title">テレアポ</h2>
  </div>
</section>
  • 文字は timeline_v2.json の cap（改行は <br>）
  • CSS は既存のトーンに合わせる（--navy 系・中央寄せ・フェードイン 0.3s 程度）。派手なアニメーションは足さない
  • No.1（0.0–9.3秒）だけは 9.3 秒と長い。2文あるので、1文目 → 2文目の順に出す（data-in で切り替え）
  • No.50（202.4–206.2）はロゴのカード。v1 のエンディングの作りを流用する

10. やってはいけないこと

  • タイムラインの秒を変えない。音声は確定済み。映像を音に合わせる
  • 音声を作り直さない。_audio/ のスクリプトは触らない（台本を直すのは篭橋さんの担当）
  • エンジン（<script> の中身）を書き換えない。タイトルカードも既存の .scene.full[data-cinema] の仕組みで作れる
  • 画面の文言を創作しない。ボタン名・見出し・ステータスは ~/work/asumo の実装と一致させる（ブランチ feat/issue-flow）
  • デプロイしない。公開は篭橋さんの判断（GitHub Pages は n2i-kagohashi/asumo-demo の feat/invoice-bulk-issue から配信中）
  • force push しない。既存の3コミットを消さない
